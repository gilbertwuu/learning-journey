# Plan · 学习计划

把“我现在理解到哪里”连接到“我希望能够理解或做到什么”。主线是学习知识，真实困难用来选择范围和举例。输出让学习者看懂为什么这样学，并为后续 Teach 提供明确起点。

## 承接与讨论

1. 沿用当前对话中的目标、情境、Probe 当前位置及逐项证据，不重新问已回答的问题。没有 Probe 时，先识别缺少哪些起点信息；不要伪造等级或强行启动整套诊断。确需补充时一次只问一个会改变路线的问题。
2. 把目标改写成可检查的能力终点，说明范围和深度。用户已认可目标就推进，不反复确认；目标存在实质歧义时提出推荐及取舍，等其回应。用户只要讨论方案时不提前教学。
3. 从终点倒推所需知识，与已表现的认识、提示后表现和具体断点对照。重要概念及关系依据可靠教材、官方教学资料或原始研究核对。区分严格前提、便于理解的教学顺序和经验关联；相关不等于前提，不把教学箭头当成生物或物理因果。
4. 给出可修订的路线。全局解释关系，近期细化到可学习、可检查的节点。不固定五个阶段、课时或完整学科覆盖；不要求补完所有基础才能讨论目标。

开始写结果前读 [四部分输出约定](references/output-format.md)。制作看板时读 [看板与复用方法](references/board.md)。已确认样例的保存位置见 [参考样例](references/preserved-example.md)。

## 固定交付的四部分

1. **学习终点与起点**：用完整段落解释目标能力、已有认识、具体断点，以及实际回答依据。
2. **知识点的关系架构图**：可交互的横向阶段学习看板；既显示关系，也显示当前哪些需要学习、哪些已有相关认识。
3. **每一段具体学到哪里**：说明学习问题、内容、深度、与其他段的连接理由及独立理解标准。
4. **第一段的具体边界**：细化近期节点、前提、检查方式及暂不展开的深度。以具体知识问题结束，不自动开始第一课。

看板沿用已确认的精简样式：详细说明通过点击节点展开，图下不重复铺设说明卡片；弹窗字号、字重与宽度按看板参考执行。

图和文字使用相同节点与含义，不让图替代解释。不能只堆课程名称、名词短语或“不懂什么”。

## 学习状态与进度

- 已有相关认识、提示后认识、具体断点、未探查、已讲未验证分别保留在证据中。“尚未探查”不等于不会；提到术语、听过解释、动画播放过都不等于掌握。
- 看板只用**蓝色＝需要学习；灰色＝已有相关认识**。灰色不宣称整章掌握，弹窗写清限于什么表现；一个大节点兼有已知与缺口时，优先拆成具体节点，避免灰色掩盖缺口。
- 标题只写知识名称，不写“先学、待学”等前缀，也不展示内部 ID 或技术分类。起点在文字说明或节点详情中解释。
- 若 B、D 支持 C，显示两条有理由的连接并保留 B、D 的证据范围。前提已具备只能说明可以从哪里理解 C，不能直接把 C 标为理解。
- 后续根据实际解释、预测、应用或迁移更新状态，保留提示来源与未确定部分。计划改变、教学进度和已掌握程度是不同信息；不输出无依据的完成百分比。

## 完成与范围

交付四部分及真实可打开的 HTML 链接，说明检查结果与限制。用户认可的路线已有明确起点时，无需追加“是否开始”确认。停止于 Plan，只有用户要求学习时才切换 Teach。理解机制与生活中的行为改善分别验证；不承诺理论学完即可解决个人问题。
