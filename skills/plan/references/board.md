# 阶段知识关系看板

## 内容建模

先确定目标、阶段、具体节点、关系及证据，再排版。每个阶段是一条横向分区，阶段内节点以横向阅读为主；跨阶段连接保留。阶段数与节点数由内容决定，不照搬公开示例。区内留白服务阅读，但不为了填空补知识。

节点必须足够具体，使“已经理解到哪、哪里仍需学习”可以分别描述。颜色仅表达学习选择：蓝色需要学或补清楚，灰色已有相关认识。提示后的局部认识也可作参考，但必须在弹窗说明提示来源；不能借灰色宣称掌握整个主题。

图例只写“需要学习”“已有相关认识”。节点只写知识名与简短说明；无“先学/待学”文字、无额外状态符号。标题和副标题整体居中。动画演示连线，不修改学习进度。

连接需要说明“前提”“帮助理解”“经验关联”或教学衔接的实际意义。不能仅因属于同一领域就连线。区分教学顺序与严格依赖，不把图展示成经过科学验证的唯一学习路径。

## 弹窗

标题：这个知识点的学习情况。显示普通语言的理解程度、目前已经理解的内容、还需要弄清楚的部分，再保留“从哪些认识接过来”和“接下来可以学什么”。不显示后端、语义护照、编写可达范围、内部 ID。理解说明有证据限制，而非成绩判词。

正文采用 13px、400 字重，小标题采用 12px、500 字重，状态说明采用 500 字重。正文延伸至卡片正常右边距；关闭和复制按钮只占标题右上角，不为其保留贯穿正文的空列。样式由 `assets/learning-panel.css` 统一提供。

主图下不生成重复的文字说明卡片；详细说明保留在节点弹窗中，资料依据可放在四部分文字说明中。

## 生成与检查

使用本 Skill 自带的 Archify 渲染器。建模前读取 `../vendor/archify/references/authoring-defaults.md`、`../vendor/archify/schemas/workflow.schema.json`；需要字段定义时读取 common schema，需要修复时读取 authoring-contract 与 delivery-contract。优先从 `../../../examples/python-basics/candidate.json` 学格式，但用新主题重新编写全部节点、关系、节点说明和视图。

生成两个输入：

- `candidate.json`：Archify workflow v2。节点 `type=frontend` 表示需要学习，`type=external` 表示已有相关认识。保留稳定 ID。`cards` 设为空数组，guided views 换为新主题内容；构建脚本也会清空 cards，避免旧样例带回底部说明区。
- `notes.json`：对象，以每个节点 ID 为键，对应三个非空字符串 `[理解程度, 已理解内容及依据, 仍需弄清楚的部分]`。未探查时明确没有证据，不编造已知认识。

构建命令（用真实绝对路径替换）：

```bash
python3 <插件目录>/skills/plan/scripts/build_board.py candidate.json notes.json .archify/workflow-learning-topic-YYYYMMDD-HHMMSS
```

脚本需要 Python 3.10+ 与 Node.js 18+，默认使用插件内固定版本的 Archify，不需要另装 Archify Skill 或 npm 包。浏览器校验需要可用的 Chrome/Chromium；缺失时如实报告未通过的门禁。它在新输出目录内复制渲染器，应用学习弹窗和居中适配，再调用完整 finalize，不修改全局 Archify，也不篡改已经交付 HTML 的校验指纹。模板接口变化会在写入前停止，需检查适配器，不盲目替换。输入已有 notes 全部嵌入成品，因此不要嵌入与学习无关的私人信息。

失败时读取具体诊断，在同一输出目录修复 candidate 或本地渲染器，按 Archify 约定重新 finalize；已有浏览器证据时使用新的 --out-dir。不要不断创建新版本绕开失败，非零退出不算完成。

自动检查与目视检查分开报告。能访问时重点检查实际点击后的弹窗、两个主题、居中、文字和连线；工具访问受阻就如实说明，不绕过限制。静态校验不能证明弹窗使用体验或学习效果。

最终交付四部分文字与 HTML 绝对路径。输出为本轮状态快照，后续状态更新依赖新证据。保留之前版本；在新主题中绝不复制参考样例的个人学习状态。

若运行环境缺少 Python、Node 或浏览器，可先交付文字和明确标为草稿的关系图，不得声称动态看板已完成。渲染器版本由插件更新管理；构建时关闭上游自动更新查询。
