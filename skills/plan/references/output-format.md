# 四部分输出约定

## 1. 学习终点与起点

终点写“能够解释、区分、判断、预测或应用什么”，包含范围。起点引用 Probe 中具体回答，解释这些表现能支撑什么、再往前哪里接不上。不用“基础不错、认知不足”等笼统词替代证据。

连成一段：为了目标需要哪类理解 → 已有认识在哪里 → 主要断点是什么 → 为什么选择这个起始节点。行为改变、产品效果等外部结果另有验证，不算作仅凭回答就能验收的学习成效。

## 2. 知识关系看板

提供 HTML，并用一段话解释读法：阶段分区、节点关系、颜色、入口。详细证据放在节点弹窗。当前状态与推荐路线共同呈现但不混为一谈；图里的节点和箭头必须与第三、四部分一致。只显示对当前目标有用的连接，避免为了视觉效果制造因果或依赖。

## 3. 每一段具体学到哪里

每段用相连的完整句子说明：

- 要解决哪个知识问题，涉及哪些概念或能力。
- 为什么与目标相关，如何接上已有认识及前后节点。
- 深度到哪里，例如定性解释、定量计算、独立应用；哪些复杂细节暂时不展开。
- 怎样检查：给新情境独立解释、预测条件变化或实际完成任务，不能仅靠自信评分或复述。

每段可以有一句单列的理解标准，但不能只剩标准而没有内容与理由。

## 4. 第一段具体边界

用“节点｜要解决的问题｜完成表现”的简洁表格列出近期学习单元。随后说明所需前提怎样随用随补，哪些细节暂时不深入，出现什么表现时可以前进、何时需缩小步骤。

不要在 Plan 内提前讲解这些节点的答案，也不要把待验证的答案提前送给后续检查。第一段具体，远处路线可调整；不以一次探查覆盖全部分支。
