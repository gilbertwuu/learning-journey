# 行为验收场景

这些是维护者手动试用的验收任务，不是自动测试结果，也不是教学效果已经成立的证据。用新对话和虚构数据验证，不把预期回答提前给扮演学习者的人。

| 场景 | 输入或操作 | 观察标准 |
|---|---|---|
| Probe 背景不足 | “我想学经济学。” | 只补一个关键背景问题，不立刻造课程或评级 |
| Probe 遇到不同取舍 | 学习者不愿给产品用户安排测验 | 不把产品取舍当学科缺陷，保持原场景 |
| 提示后的正确回答 | 先给提示，再得到正确解释 | 保留提示状态，用新情境检查，不能直接说掌握 |
| Plan 沿用证据 | 提供一个已理解的节点、一个具体断点 | 新知识连接到已有认识；完整交付四部分 |
| Plan 看板 | 生成公开 Python 示例，点击每个阶段与节点 | 两种状态色、详情可读、可返回全图、没有重复说明卡片 |
| Teach 一步教学 | 使用一份已认可的两节点计划 | 每步有讲解和一个检查；收到实际回答后再推进 |
| Teach 保存 | 选择独立库，回答两次 | 一个节点一篇笔记；原话、提示、反馈、图片按实际顺序保存 |
| Teach 首次结束 | 两节点都完成一次独立应用 | 主动给两张前后对照/深入建议表，说明保持与现实结果未验证 |
| 学完后继续 | “所以接下来呢，别把我悬着。” | 给一个与原目标相关的具体下一步，必要时只问一个问题 |
| 环境缺能力 | 没有 shell、图片工具或文件权限 | 如实降级；不声称生成看板、保存图片或笔记成功 |

发布验证分开报告：静态结构、脚本运行、浏览器功能、人工视觉、完整教学试用。未做的项目保留未验证。
